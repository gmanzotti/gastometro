CONTEXTO
────────────────────────────────────────────────────────────────────

O Gastômetro é um painel de monitoramento dos gastos do Governo Federal,
desenvolvido pela Assessoria Econômica da Presidência. Ele consolida dados
do Tesouro Nacional (RTN — Resultado do Tesouro Nacional) e os apresenta
em formato de fácil leitura para comunicação institucional.

O produto tem dois objetivos distintos, que implicam dois produtos
complementares — e é essa distinção que orienta toda a proposta abaixo.

OS DOIS PRODUTOS
────────────────────────────────────────────────────────────────────

PRODUTO 1 — Site público (demanda da Presidência)
  Objetivo: comunicação externa, aberta ao público geral — imprensa,
  governo, opinion makers. Peça de advocacy institucional da FIESP.

  Conteúdo central:
    - Contador em tempo real dos gastos acumulados do Governo Federal no ano
    - Composição das despesas por categoria (Previdência, Pessoal, etc.)
    - Top 5 rubricas de maior peso no mês e no acumulado 12 meses
    - Dados de resultado primário

  Requisito técnico que define a ferramenta:
    O contador em tempo real é implementado em JavaScript — ele calcula
    automaticamente R$/segundo e atualiza o display 10 vezes por segundo,
    criando o efeito visual de um contador contínuo. Esse recurso não pode
    ser replicado em Power BI: a plataforma não suporta JavaScript
    customizado por restrições de segurança. Isso não é uma preferência
    de ferramenta — é uma limitação técnica objetiva que define o uso
    do Streamlit (biblioteca Python de interface web) para este produto.

  Acesso: público, sem autenticação. URL própria da FIESP.


PRODUTO 2 — Dashboard interno (para os filiados)
  Objetivo: disponibilizar os dados fiscais dentro da estrutura existente
  de dashboards da FIESP, para acesso pelos filiados.

  Ferramenta: Power BI, integrado à base de dashboards já existente.
  Acesso: autenticado, restrito a filiados — como os demais painéis da casa.

  Nota: este produto serve um público completamente diferente do Produto 1.
  Não são concorrentes — são complementares. Um filiado autenticado acessa
  o Power BI interno; qualquer pessoa acessa o site público.


COMUNICAÇÃO ATIVA — WHATSAPP (demanda da Presidência)
────────────────────────────────────────────────────────────────────

A Presidência solicitou o envio automático de mensagem via WhatsApp sempre
que a base de dados for atualizada (mensalmente), com os grandes números
do mês e um PDF de resumo executivo.

Funcionamento previsto:
  1. Pipeline de dados roda e atualiza os arquivos
  2. Script gera automaticamente o PDF do relatório mensal
  3. Mensagem WhatsApp é enviada para lista de contatos com opt-in,
     contendo os números do mês e o PDF em anexo (MENSAGENS PRECISARÃO DE APROVAÇÃO: NÃO-AUTOMATIZADAS)

Requisitos para implementação:
  - Conta WhatsApp Business API (aprovação pela Meta — processo leva 1 a 7
    dias úteis; precisa ser iniciado o quanto antes)
  - Template de mensagem aprovado pela Meta antes do primeiro envio
  - Definição de orçamento: mensagens template têm custo por envio
  - Lista de destinatários com opt-in (exigência da Meta)

Item com maior prazo de espera do projeto — recomenda-se iniciar o
processo de aprovação imediatamente, em paralelo com o restante.


HOSPEDAGEM E VERSIONAMENTO
────────────────────────────────────────────────────────────────────

Situação atual:
  O site está hospedado no Streamlit Community Cloud (plano gratuito),
  vinculado a repositório GitHub pessoal. O plano gratuito suspende o
  app após períodos de inatividade, causando demora de 20–60 segundos
  no primeiro acesso após a suspensão — comportamento inadequado para
  um produto público institucional.

Proposta:

  VERSIONAMENTO — Azure DevOps (imediato)
    Migração do repositório para o Azure DevOps da FIESP, com pipeline
    de CI/CD configurado para deploy automático a cada atualização de
    código. Implementação imediata e sem impacto no produto.

  HOSPEDAGEM — Azure App Service (produto público)
    O Azure App Service é um serviço da Microsoft para hospedar
    aplicações web em servidores dedicados. Ele executa o app Streamlit
    continuamente, sem suspensões, respondendo a acessos instantaneamente.
    O Streamlit (biblioteca Python) roda dentro do App Service — não há
    mudança no código da aplicação, apenas na infraestrutura que o executa.

    Benefícios:
      - App sempre disponível, sem cold start
      - URL própria da FIESP (ex: gastometro.fiesp.com.br) configurada
        via DNS no próprio Azure
      - Infraestrutura sob gestão da TI da FIESP
      - Deploy automático integrado ao Azure DevOps: qualquer push no
        repositório atualiza o site automaticamente

    Tier recomendado: B1 ou P1v3 (suficiente para a carga esperada)

  DADOS — Power BI interno
    O pipeline de dados gera arquivos .parquet que o Power BI lê
    nativamente. Para que o Power BI Service (acesso online pelos
    filiados) atualize automaticamente, os arquivos precisam estar em
    uma fonte acessível na nuvem — SharePoint, OneDrive corporativo
    ou Azure Blob Storage. A configuração do gateway de dados e da
    fonte cloud é responsabilidade da TI.
